# Точка ремонта — развёртывание и восстановление

Одностраничный лендинг автосервиса в Москве. HTML, CSS и JavaScript без сборки и сторонних пакетов; изображения и шрифт находятся в проекте. На компьютере название и фотография расположены рядом, на телефоне — друг под другом. Машина на подъёмнике поднимается и трижды моргает фарами; фоновая машина движется при прокрутке.

Репозиторий [pasha-tsaran/Landing](https://github.com/pasha-tsaran/Landing), рабочая ветка `main`.

**Форма демонстрационная:** проверяет заполнение, но не отправляет заявки и не сохраняет введённые данные. Базы данных, постоянных томов и хранилища заявок нет. При восстановлении нужно вернуть исходники, изображения и настройки запуска.

## Что установить

- Git.
- На Windows — Docker Desktop с запущенными Linux-контейнерами; на Linux — Docker Engine и плагин Docker Compose.
- Compose с поддержкой `--wait` и `--wait-timeout`. Проверьте доступность: `docker compose up --help`.
- Node.js 24 или новее нужен только для запуска и тестов без Docker.

Проверьте установку:

```text
git --version
docker version
docker compose version
```

Для первого клонирования нужен доступ к GitHub, для первой сборки — к Docker Hub. Готовая автономная резервная копия позволяет восстановиться без них.

## Первый запуск через Docker

Откройте терминал в папке, где хотите хранить проект:

```text
git clone --branch main https://github.com/pasha-tsaran/Landing.git autoservice
cd autoservice
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 120
docker compose ps
```

Если проект уже скачан, перейдите в его папку и начните с `docker compose config --quiet`. Все дальнейшие команды `docker compose` выполняются в папке с `compose.yaml`.

У сервиса `landing` должен появиться статус `healthy`. Откройте [http://127.0.0.1:4183](http://127.0.0.1:4183). Проверка готовности должна вернуть `ok`:

```powershell
# Windows / PowerShell
(Invoke-WebRequest 'http://127.0.0.1:4183/healthz' -UseBasicParsing).Content
```

```bash
# Linux
curl --fail http://127.0.0.1:4183/healthz
```

`--wait-timeout 120` ограничивает ожидание готовности после сборки; время самой сборки в этот предел не входит. Поведение параметров описано в [документации Docker Compose](https://docs.docker.com/reference/cli/docker/compose/up/).

Конфигурация использует имя проекта `tochka-remonta`, образ `tochka-remonta-landing:latest`, Node.js 24 Alpine с закреплённым digest, пользователя `node` и файловую систему контейнера только для чтения. Контейнер перезапускается по правилу `unless-stopped`, пока работает Docker. На Windows после перезагрузки компьютера нужно запустить Docker Desktop.

### Порт и доступ снаружи

Строка `127.0.0.1:4183:4183` в `compose.yaml` означает: порт 4183 доступен только на компьютере, где работает Docker. Для другого локального порта замените её, например, на `127.0.0.1:4184:4183`, затем повторите запуск. После этого адрес сайта и проверки готовности используют порт 4184; внутренний порт контейнера остаётся 4183.

Для публикации на Linux-сервере выполните тот же запуск на сервере. Укажите его IP в DNS своего домена и настройте HTTPS-прокси на **этом же сервере**, направив запросы на `http://127.0.0.1:4183`. Порт 4183 оставьте локальным; снаружи открываются порты 80 и 443. Если прокси работает в отдельном контейнере, его `127.0.0.1` относится к самому прокси: потребуется общая Docker-сеть и адрес `landing:4183`.

Пример для Nginx, установленного на хосте. Замените `example.com` своим доменом; сертификат и ключ должны уже существовать по указанным путям:

```nginx
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name example.com;
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:4183;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

После добавления конфигурации проверьте её и примените:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

Проверьте `https://ВАШ-ДОМЕН/healthz` и главную страницу с другого устройства. Настройка домена, выпуск и продление сертификата выполняются на выбранном сервере отдельно. Передача запросов описана в [документации Nginx](https://docs.nginx.com/nginx/admin-guide/web-server/reverse-proxy/).

### Открытие серверного сайта из Docker Desktop на ПК

Для перехода на `http://193.187.96.95:8001/` из списка локальных контейнеров есть отдельный файл `compose.server-link.yaml`. Он запускает небольшой локальный контейнер, который перенаправляет браузер на серверный сайт. Это ссылка для удобства, а не копия сайта или средство управления сервером.

Нужен локальный образ `tochka-remonta-landing:latest`, созданный при обычной сборке проекта. Запуск из папки проекта:

```text
docker compose -f compose.server-link.yaml up -d --wait --wait-timeout 60
```

В Docker Desktop раскройте группу `autoservice-server`, найдите контейнер `autoservice-server-link` и нажмите порт `8001:8001`. Браузер откроет локальный адрес и сразу перейдёт на `http://193.187.96.95:8001/`. Остановка этого контейнера отключает только локальную ссылку; сам сайт продолжает работать на сервере. Статус `healthy` у ссылки означает, что перенаправление работает, а не что удалённый сайт доступен.

Если адрес сервера поменяется, обновите `target` в `compose.server-link.yaml` и повторите запуск. Если локальный порт 8001 занят, замените первый порт в строке `127.0.0.1:8001:8001`, например на `127.0.0.1:8002:8001`.

## Обновление и откат

Перед обновлением сделайте резервную копию по следующему разделу. Проверьте состояние файлов:

```text
git status --short
```

Если команда показывает изменения, сначала сохраните нужные правки отдельным коммитом или копией файлов. Не переключайте версию поверх несохранённых изменений. При чистой рабочей папке:

```text
git switch main
git pull --ff-only origin main
docker compose up -d --build --wait --wait-timeout 120
docker compose ps
```

Успешный `git pull` не обновляет работающий контейнер: для этого нужна команда со сборкой. При замене единственного контейнера возможен короткий перерыв в работе сайта. После обновления проверьте `/healthz`, первый экран, мобильное меню, выбор услуги и проверку демоформы.

Чтобы вернуться к сохранённому коммиту, посмотрите историю и замените `COMMIT` его хешем:

```text
git log --oneline -10
git switch --detach COMMIT
docker compose up -d --build --wait --wait-timeout 120
```

Это переключение версии для развёртывания, без переписывания истории GitHub. Для возврата к последней версии выполните последовательность обновления выше. Если доступ к Docker Hub потерян, используйте сохранённый образ из автономной копии.

## Резервная копия

Копию создавайте из ветки `main` с чистой рабочей папкой, после успешной сборки и проверки текущей версии. Иначе сохранённые исходники и запущенный образ могут относиться к разным версиям.

Следующие команды работают в PowerShell и Bash. Папка `../autoservice-backup` должна быть новой; для каждой следующей копии используйте другое имя, например с датой:

```text
mkdir ../autoservice-backup
git bundle create ../autoservice-backup/autoservice.bundle --branches --tags
git bundle verify ../autoservice-backup/autoservice.bundle
git log -1 --format=%H --output=../autoservice-backup/commit.txt
docker image save --output ../autoservice-backup/autoservice-image.tar tochka-remonta-landing:latest
docker image inspect tochka-remonta-landing:latest --format '{{.Os}}/{{.Architecture}}'
```

Сохраните показанную платформу рядом с копией. Готовый образ рассчитан на указанную архитектуру; для сервера с другой архитектурой потребуется сборка из исходников. Например, образ `linux/amd64` рассчитан на соответствующий Linux-хост или совместимую среду Docker.

Проверьте успешное завершение каждой команды. Перенесите папку копии на другой диск или отдельное хранилище. Дополнительно можно сравнить контрольную сумму архива после переноса:

```powershell
Get-FileHash ../autoservice-backup/autoservice-image.tar -Algorithm SHA256
```

```bash
sha256sum ../autoservice-backup/autoservice-image.tar
```

Состав копии:

| Файл | Что восстанавливает |
| --- | --- |
| `autoservice.bundle` | История локальных веток и тегов со всеми закоммиченными файлами, включая изображения, шрифт, Dockerfile и Compose |
| `autoservice-image.tar` | Готовый образ для запуска без повторной сборки |
| `commit.txt` | Хеш версии исходников на момент копирования |

Bundle не содержит незакоммиченные изменения, игнорируемые файлы или настройки хоста. Отдельно сохраните локально изменённый `compose.yaml`, конфигурацию прокси, необходимые секреты и порядок восстановления TLS-сертификатов. Эти секреты не отправляются в GitHub. Восстанавливать значения демоформы нечего: они не сохраняются.

См. [Git bundle](https://git-scm.com/docs/git-bundle) и [Docker image save](https://docs.docker.com/reference/cli/docker/image/save/).

## Восстановление

### Из GitHub с доступом в интернет

На новом компьютере установите Git и Docker, затем выполните команды первого запуска. Для конкретной сохранённой версии после клонирования выполните `git switch --detach COMMIT`, используя хеш из `commit.txt`, и только затем собирайте контейнер.

Если пропал только контейнер, а папка проекта сохранилась:

```text
docker compose up -d --build --wait --wait-timeout 120
```

Если Docker-образ тоже сохранился и соответствует нужной версии, пересборка не нужна:

```text
docker compose up -d --no-build --pull never --wait --wait-timeout 120
```

### Из автономной копии

Положите папку `autoservice-backup` в выбранный каталог и откройте терминал **в этом каталоге**, а не внутри папки копии. Git и Docker должны быть уже установлены. Каталог `autoservice-restored` должен отсутствовать, а прежний экземпляр сайта не должен занимать порт 4183.

```text
git clone --branch main ./autoservice-backup/autoservice.bundle autoservice-restored
cd autoservice-restored
git remote set-url origin https://github.com/pasha-tsaran/Landing.git
git rev-parse HEAD
```

Сравните результат `git rev-parse HEAD` с `../autoservice-backup/commit.txt`: версии должны совпадать. При несовпадении найдите нужную копию перед запуском. Затем загрузите образ и запустите сайт:

```text
docker image load --input ../autoservice-backup/autoservice-image.tar
docker compose config --quiet
docker compose up -d --no-build --pull never --wait --wait-timeout 120
docker compose ps
```

Если при создании копии использовалась другая папка, замените её имя в командах. `git remote set-url` только возвращает адрес GitHub для будущих обновлений; для самого восстановления интернет не нужен. Образ загружается с исходным именем, ожидаемым `compose.yaml`; `--no-build --pull never` исключает сборку и загрузку образов из реестра. См. [Docker image load](https://docs.docker.com/reference/cli/docker/image/load/).

Верните сохранённые настройки прокси и сертификаты, если это публичный сервер. Затем проверьте `healthy`, ответ `ok` от `/healthz`, загрузку изображений, мобильное меню и демоформу. При необходимости откройте страницу с принудительным обновлением, чтобы убрать старую версию из кеша браузера.

## Управление и диагностика

```text
docker compose ps
docker compose logs --tail 100 landing
docker compose restart landing
```

`restart` перезапускает текущий контейнер, но не применяет изменённые исходники или настройки Compose. Для применения изменений используйте `up -d --build --wait`.

Для плановой остановки:

```text
docker compose down
```

Исходники и собранный образ останутся. В этом проекте нет томов с данными. Для возобновления выполните команду запуска.

| Проблема | Действие |
| --- | --- |
| Docker недоступен | Запустите Docker Desktop или службу Docker; проверьте `docker version` |
| Неизвестен параметр `--wait` | Обновите Docker Compose и проверьте `docker compose up --help` |
| Порт 4183 занят | Остановите прежний экземпляр или смените внешний порт в `compose.yaml` |
| Контейнер `unhealthy` или ожидание завершилось ошибкой | Посмотрите `docker compose logs --tail 100 landing`; проверьте `/healthz` |
| После изменений видна старая версия | Пересоберите контейнер; обновите страницу без кеша |
| Новый файл изображения возвращает 404 | Добавьте путь в разрешённый список `server.cjs` и убедитесь, что Dockerfile и `.dockerignore` включают файл; пересоберите образ |
| Сайт доступен на сервере, но не через домен | Проверьте DNS, сертификат и конфигурацию прокси; напрямую порт 4183 доступен только локально |
| Нет доступа к Docker Hub | Восстановите сохранённый образ либо дождитесь доступа для сборки |

Сервер пишет сообщения о запуске и ошибках, но не ведёт журнал запросов. У прокси и хостинга могут быть собственные журналы.

## Запуск и проверки без Docker

Установите Node.js 24 или новее. Установка пакетов не требуется:

```text
npm run check
npm test
npm start
```

В Windows можно также открыть `Запустить.cmd`. Сервер по умолчанию слушает `127.0.0.1:4183`; остановка — Ctrl+C. Если Docker уже занимает этот порт, для временного запуска используйте другой:

```powershell
$env:PORT = '4184'
npm start
```

```bash
PORT=4184 npm start
```

`HOST` позволяет изменить интерфейс прослушивания. Можно открыть `index.html` напрямую, но защитные HTTP-заголовки работают только через сервер. Браузерные сценарии и скриншоты в `.taste-skill/` — локальные материалы проверок, они не входят в Git или Docker-образ.

## Файлы и ограничения макета

| Путь | Назначение |
| --- | --- |
| `index.html` | Восемь блоков лендинга, контакты, политика и отдельное согласие демоформы |
| `styles.css` | Чёрно-жёлтая палитра, адаптивность и оформление |
| `app.js` | Отдельные функции инициализации меню, записи, документов, движения при прокрутке, подъёмника и появления блоков |
| `server.cjs` | Сервер, разрешённый список файлов, защитные заголовки и `/healthz` |
| `assets/` | Изображения и локальный шрифт; кадры подъёмника в `assets/lift/` |
| `Dockerfile`, `compose.yaml`, `.dockerignore` | Сборка и запуск контейнера |
| `tests/server.test.cjs` | Проверки ресурсов, HTTP-методов, готовности и защиты служебных файлов |
| `REVIEW.md`, `DESIGN.md`, `IMAGE-PROMPTS.md` | Ревью, решения по дизайну и происхождение изображений |

Основная фотография сохраняет полный кадр 4:3. Анимация подъёма запускается один раз при появлении фотографии и повторяется после обновления страницы. При настройке уменьшения движения в системе она отключается. Без JavaScript фотография остаётся статичной; демоотправка недоступна.

Москва, название и часы 08:00–20:00 заданы для макета. Дни работы, реальный телефон, почта, цены, акции и условия обслуживания требуют подтверждения владельцем. Фотографии являются иллюстрациями. TikTok Sans распространяется по SIL Open Font License; текст лицензии — `assets/fonts/OFL.txt`.

Перед приёмом настоящих заявок нужны действующие реквизиты оператора, документы для реального процесса обработки персональных данных и серверный обработчик. В текущей версии CSP запрещает отправку формы и сетевые соединения из скрипта; сервер принимает только GET и HEAD. Развёртывание этой версии само по себе не подключает приём заявок.
